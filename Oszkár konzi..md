> Format capability propagation rules complete the cross-layer mechanism. When a governance annotation or domain requirement demands a capability, propagation rules eliminate incompatible format classes by negative elimination: for a \texttt{Formatted\_Credential} \(f\) where \texttt{supports\_predicate\_proof} must hold, any format class that cannot provide predicate proofs (SD-JWT-VC, JWT-VC, mdoc, JSON-LD) is set to \textbf{false}, leaving only AnonCreds. The mechanism is the same as the trace consistency rules (\texttt{prop\_t}, \texttt{prop\_s}): Refinery's four-valued interpretation distinguishes \textbf{must} (committed true), \textbf{must not} (committed false), \textbf{may} (possibly true), and \textbf{may not} (possibly false), and propagation rules convert open assignments to committed false when a constraint excludes them. The key distinction is between propagation rules, which guide generation by narrowing the design space, and error predicates such as \texttt{governance\_conflict}, which check committed assignments and report violations. This distinction enables the metamodel to serve both as a consistency checker for existing designs and as an efficient generative tool for DSE.
