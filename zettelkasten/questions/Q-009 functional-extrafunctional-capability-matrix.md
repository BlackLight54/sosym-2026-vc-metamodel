The current FSL models six **functional** capability predicates ([[C-016 format-capability-matrix]]).
Should the journal extension add an **extra-functional** capability matrix (performance, resource cost,
verifier-side requirements) and a **composability/interoperability** relation — which format combines
with which, which interoperates with which?

## Why it matters
Strengthens the FSL beyond binary capability flags and supports the expressiveness claim
([[K-006 expressiveness-validation]]). The Todoist thread frames it as a matrix usable by government and
EDIH-SME audiences, with eIDAS 2.0 framing — i.e. a practitioner-facing artifact, not only a formal one.

## Status
Open. Requires defining extra-functional dimensions formally and deciding whether composability is a
metamodel relation or an evaluation overlay. The dual-issuance rule ([[C-033 dual-issuance-mandate]])
already forces a composability question: a PID must be simultaneously valid in two formats.
