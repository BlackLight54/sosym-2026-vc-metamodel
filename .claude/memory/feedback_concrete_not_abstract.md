---
name: "Concrete language over abstract compression"
description: "Draft prose must use concrete examples and plain language — abstract compressed sentences get rejected as incomprehensible"
type: feedback
---

When drafting defensive or explanatory sentences, use concrete language with specific examples. Do not compress multiple abstract ideas into a single dense sentence.

**Why:** Martin rejected abstract compressed prose ("I don't get this sentence. Please, what the fuck? It's so bad") — e.g., "Each excluded family operates at runtime; including them would extend scope beyond design-time schema analysis without strengthening cross-layer constraint detection." The rewrite that landed used concrete verbs and a grounding distinction: "These three families govern how a credential with a given structure is used (signed, presented, revoked), not how that structure is designed."

**How to apply:** Before proposing a sentence, check: would a Business Manager reviewer understand this on first read? If the sentence requires unpacking, split it or add a concrete example. One concrete example beats three abstract clauses.
